# RAG 샘플 문서

## 1. RAG 란 무엇인가

RAG(Retrieval-Augmented Generation, 검색 증강 생성)는 질문에 답하기 전에
외부 문서 저장소에서 관련 내용을 먼저 검색한 뒤, 그 내용을 근거로 언어 모델이
답변을 생성하는 방식이다. 모델을 재학습시키지 않아도 최신 사내 문서를
반영할 수 있고, 답변의 출처를 함께 제시할 수 있다는 장점이 있다.

## 2. 파이프라인 4단계

1. 적재(Load): txt, md, pdf 등의 원본 문서를 읽어 들인다.
2. 분할(Chunk): 문서를 일정 길이의 조각으로 나눈다. 조각 사이에 일부를
   겹치게(overlap) 두면 문맥이 잘리지 않는다.
3. 임베딩(Embed): 각 조각을 숫자 벡터로 변환해 저장한다.
4. 검색(Retrieve): 질문도 같은 방식으로 벡터화한 뒤, 코사인 유사도가
   가장 높은 조각 top-k 를 찾아 모델에 함께 전달한다.

## 3. 임베딩 모델 선택 기준

- 로컬 우선: Ollama 의 nomic-embed-text 는 768차원 벡터를 만들며,
  인터넷 연결 없이 동작하고 비용이 들지 않는다.
- 클라우드: OpenAI 의 text-embedding-3-small 은 1536차원이며 품질이
  안정적이지만 호출당 비용이 발생한다.
- 한번 색인한 뒤에는 임베딩 모델을 바꾸지 않는 것이 좋다. 모델이 바뀌면
  벡터 공간이 달라져 기존 색인과 비교할 수 없으므로 전체 재색인이 필요하다.

## 4. 청크 크기 설계

청크가 너무 작으면 문맥이 부족하고, 너무 크면 검색 정밀도가 떨어진다.
일반적으로 500~1000자, 겹침은 청크 크기의 10~20% 를 권장한다.
이 프로젝트의 기본값은 size 800, overlap 120 이다.

## 5. OpenCode 와 MCP

OpenCode 는 MCP(Model Context Protocol) 서버를 통해 외부 도구를 사용한다.
RAG 검색기를 MCP 서버로 만들면 OpenCode 가 대화 중에 search_docs 도구를
스스로 호출해 근거를 찾을 수 있다. OpenCode 설정 파일의 mcp 항목에
type: local 과 command 배열을 등록하면 된다.

## 6. 자주 겪는 문제

- 검색 결과가 비어 있음: 색인이 아직 안 되었거나 임베딩 제공자가 꺼져 있다.
- 차원 불일치 오류: 색인할 때와 검색할 때 임베딩 모델이 다르다.
- 응답이 느림: 청크 수가 많으면 순수 파이썬 코사인 계산이 느려진다.
  이때는 저장소를 여러 개로 나누거나 벡터 인덱스 라이브러리 도입을 검토한다.
- Ollama 연결 실패: ollama serve 가 실행 중인지 확인한다.
